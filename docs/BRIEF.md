```
## Что произвести

Из референсов вынеси принципы, а не элементы: material-first подача, крупная типографика,
fullscreen-секции, editorial-раскладки, работа с текстурой и торцом материала, минималистичная
навигация, горизонтальные секции, сдержанное движение, иерархия «материал → интерьерный контекст».

Главный герой сайта — МАТЕРИАЛ, не компания и не текст. Пользователь должен «чувствовать»
поверхность глазами: срез плиты, торец, кромка, столешница под светом, применение в интерьере.

Proposal состоит ровно из 5 частей, в этом порядке.

### Часть A — Визуальная система
1. Visual direction — 3–5 предложений: как сайт ощущается, за счёт чего именно.
2. Color system — 4–6 цветов: HEX, роль, обоснование от материала (не от моды).
3. Typography — гарнитуры (display + text), шкала, поведение oversized-заголовков.

### Часть B — Секции (6–8 штук, не больше)
Каждая секция описывается СТРОГО по этому шаблону, без свободной прозы:

```
S<n>. <Название> — <роль в нарративе страницы, 1 предложение>
Композиция : <тип раскладки + что физически где на 1440px>
Материал   : [PLACEHOLDER: <что в кадре>, <свет>, <соотношение сторон>]
Копирайт   : H: «...» / SUB: «...» / micro: «...»
Motion     : <что анимируется> ← <триггер>, <длительность/easing>; reduced-motion: <фолбэк>
Mobile     : <как перестраивается композиция — не «в одну колонку»>
Pattern-tag: <короткий тег раскладки, напр. editorial-offset, sticky-swap, full-bleed-type>
```

### Часть C — Продуктовые механики
4. Product presentation — как показаны ЛДСП, ЛМДФ, столешницы, чем отличается подача каждого.
5. Decor Explorer — интерактивный выбор декоров: категории (дерево / светлые / тёмные / камень /
   однотонные), что меняется при выборе (крупная поверхность, интерьерный кадр, фон, название,
   артикул), состояния hover/active/loading, поведение на touch. Данные — из <decor_catalog>.
6. Mobile adaptation — как меняется КОМПОЗИЦИЯ на 390px, а не факт коллапса.

### Часть D — Реестр паттернов (обязательный артефакт, не проза)
Таблица: `Pattern-tag | секции | счётчик`.
Правило: ни один pattern-tag не встречается более 2 раз. Счётчик 3+ → переработай секцию
и покажи в таблице уже исправленное состояние.

### Часть E — Контроль
7. Anti-slop check — таблица `Запрещённый приём | где напрашивался | что вместо него`.
   Минимум 6 строк, каждая привязана к конкретной секции из части B.
8. Image sourcing plan — где стоят placeholder-блоки, как помечены, каким одним пропом
   заменяются на реальное фото без переписывания разметки.
9. Acceptance-отчёт — по каждому пункту `PASS/FAIL + доказательство`:
   - ни один pattern-tag не повторяется >2 раз (ссылка на часть D);
   - ≥3 секции построены НЕ на сетке карточек (перечислить номера);
   - Hero не использует схему «текст слева / картинка справа»;
   - ни одной фразы из запрещённого списка;
   - ни одной цифры/клиента/отзыва вне <company_facts>;
   - все изображения — помеченные placeholder-блоки.
   Любой FAIL чинится ДО выдачи ответа; в ответ уходит только PASS.

## Запрещено (AI slop)

Раскладка: generic SaaS layout; hero «текст слева / картинка справа»; одинаковые карточки
в каждом блоке; feature-cards с иконкой в кружке; 4-колоночный футер.
Стиль: rounded-xl везде; pill-кнопки везде; бессмысленные градиенты; сине-фиолетовая
стартап-палитра; glow, glassmorphism, плавающие блобы.
Контент: стоковые бизнес-фото; вымышленные отзывы, статистика, клиенты; lorem ipsum.
Копирайт-штампы: «Качество, которому доверяют», «Ваш надёжный партнёр», «Создаём будущее»,
«Инновационные решения», «Воплощаем мечты», «Комплексные решения нового поколения»,
«Создаём пространство для ваших идей».

Вместо них: конкретика о материале, размере, обработке, сроке, применении.

## Краевые случаи

- Референс не открывается → пометь это одной строкой и работай по общим принципам; не выдавай
  общие рассуждения за разбор конкретного сайта.
- Нужного факта нет в <company_facts> → секция строится без него. Не «более 10 лет на рынке»,
  не «сотни клиентов», не «примерно».
- Просится красивая цифра (объём склада, срок поставки) → либо факт из тега, либо формулировка
  без цифры.
- Секция не проходит anti-slop → переработай её ДО выдачи, не приписывай оговорку после.
- Секций набирается 10+ → сократи до 6–8 сильных. Количество секций не является целью.

Формат ответа: markdown, части A–E по порядку, шаблон секций соблюдён дословно, таблицы —
таблицами. После части E — остановись.
```

```
## Ключевое требование по изображениям

Все кадры проходят через один компонент. Placeholder и реальное фото взаимозаменяемы
через один проп — разметка при замене не меняется.

<example name="MaterialFrame">
// components/MaterialFrame.tsx
type MaterialFrameProps = {
  /** Реальный кадр. Пока не снят — undefined, рендерится placeholder. */
  src?: string
  /** Описание кадра: идёт и в alt, и в текст плейсхолдера. */
  frame: string
  ratio: '16/9' | '4/5' | '3/4' | '1/1'
  className?: string
}

// src задан    → <Image src={src} alt={frame} fill sizes="..." />
// src не задан → блок с рамкой и текстом `[PLACEHOLDER: ${frame}]`, тот же aspect-ratio,
//                тот же размер бокса → замена фото не вызывает layout shift.

// Использование одинаковое в обоих случаях:
<MaterialFrame frame="торец ЛДСП 18 мм, жёсткий боковой свет" ratio="3/4" />
</example>

## Motion

Разрешено: smooth scroll, text reveal, image clipping, parallax, scroll-driven transitions,
horizontal scroll, sticky-секции, staggered text, hover-состояния, анимированная смена декора.
Запрещено: scroll-jacking, анимации, мешающие читать и кликать, автоплей-карусели.
Обязательно: `prefers-reduced-motion: reduce` отключает transform/clip-анимации и оставляет
мгновенную смену состояний. Проверяется вручную перед сдачей.

## Адаптив

Отдельно продумай 1440+, laptop (1280), tablet (768), mobile (390). На мобильном сохраняется
арт-дирекшн: oversized-типографика масштабируется, композиция перестраивается по описанию
из proposal, motion упрощается. `desktop-grid → flex-col` не является адаптацией.

## Производительность

next/image везде, lazy-loading ниже первого экрана, шрифты через next/font, отсутствие
горизонтального overflow на всех брейкпоинтах, отсутствие layout shift при замене
placeholder → фото, отсутствие hydration-ошибок и ошибок в консоли.

## Краевые случаи

- Эффект из proposal не воспроизводится на выбранном стеке → реализуй ближайший по смыслу
  и запиши строку «отклонение от proposal».
- Данных для декора нет в <decor_catalog> → рендери плейсхолдер-плитку с пометкой TODO,
  не придумывай артикул.
- Секция требует фото, которого нет → MaterialFrame без src, никаких стоков.
- Тайпчек или сборка падают → чини до зелёного, не сдавай с ошибками.

## Гейты перед сдачей (каждый — PASS/FAIL с доказательством)

1. `npx tsc --noEmit` → 0 ошибок.
2. `npm run build` → успешная сборка.
3. Обход 1440 / 1280 / 768 / 390: нет горизонтального overflow, нет пустой консоли.
4. Все hover-состояния отрабатывают; touch-устройство не залипает в hover.
5. `prefers-reduced-motion: reduce` — сайт полностью читаем и используем.
6. Anti-slop лист — построчно по итоговой вёрстке, не по намерению.
7. Запрещённые фразы — grep по репозиторию, 0 совпадений.
8. Цифры/клиенты/отзывы вне <company_facts> — 0 совпадений.
9. Реестр паттернов из proposal сверен с реальной вёрсткой: ни один тег не превышен.

Формат ответа: список реализованных секций (по одной строке), таблица гейтов с результатами,
список отклонений от proposal (или «нет»), команды запуска dev и build.
```
